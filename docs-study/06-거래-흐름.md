# 거래 흐름

## 전체 시나리오 개요

**Alice**가 **1 ETH**를 가지고 있고, **Bob**의 **100 DAI**와 교환하고 싶은 상황입니다.

```
Alice (1 ETH)  ←──거래──▶  Bob (100 DAI)
```

---

## 단계별 흐름

### Phase 1: 입금 (Mint)

양쪽 모두 자신의 토큰을 ZK-DEX에 입금합니다.

#### Alice: ETH 입금

```
1. Alice가 1 ETH를 컨트랙트에 전송
2. mint_burn_note 증명 생성
3. 노트 생성: NoteA(owner=AlicePk, value=1ETH, token=ETH)
4. 온체인: notes[NoteA.hash] = Valid
```

```javascript
// 코드 예시
const aliceNote = await noteStore.mint(parseEther('1'), ETH_TOKEN_TYPE)
// aliceNote = { owner0: AlicePkX, owner1: AlicePkY, value: 1e18, tokenType: 0, ... }
```

#### Bob: DAI 입금

```
1. Bob이 100 DAI를 컨트랙트에 approve 후 전송
2. mint_burn_note 증명 생성
3. 노트 생성: NoteB(owner=BobPk, value=100DAI, token=DAI)
4. 온체인: notes[NoteB.hash] = Valid
```

**현재 상태:**
```
Alice: NoteA (1 ETH, Valid)
Bob:   NoteB (100 DAI, Valid)
```

---

### Phase 2: 주문 생성 (Make Order)

Alice가 "1 ETH를 DAI로 교환하고 싶다"는 주문을 생성합니다.

```
1. make_order 증명 생성 (NoteA 소유 증명)
2. 주문 생성: Order(source=ETH, target=DAI, price=100)
3. NoteA 잠금: notes[NoteA.hash] = Trading
4. 온체인에 주문 저장
```

```javascript
// 코드 예시
const orderId = await orderStore.makeOrder(
  aliceNote,
  DAI_TOKEN_TYPE,  // 원하는 토큰
  parseEther('100') // 가격: 1 ETH = 100 DAI
)
```

**현재 상태:**
```
Alice: NoteA (1 ETH, Trading) ← 주문에 잠김
Bob:   NoteB (100 DAI, Valid)
Order: { id: 0, maker: NoteA, source: ETH, target: DAI, price: 100, state: Created }
```

---

### Phase 3: 주문 수락 (Take Order)

Bob이 Alice의 주문을 수락합니다.

```
1. Bob이 NoteB로 스테이크 노트 생성
2. 스테이크 노트는 "스마트 노트"
   - owner0 = NoteA.hash >> 128
   - owner1 = NoteA.hash & MASK
   → Alice만 이 노트를 체결할 수 있음!
3. take_order 증명 생성
4. NoteB 잠금: notes[NoteB.hash] = Trading
5. 스테이크 노트 생성: notes[Stake.hash] = Trading
```

```javascript
// 코드 예시
await orderStore.takeOrder(orderId, bobNote)
```

**스마트 노트의 핵심:**
```
StakeNote.owner0 = NoteA.hash >> 128
StakeNote.owner1 = NoteA.hash & ((1<<128) - 1)

→ 이 노트의 "소유자"는 NoteA의 해시에서 파생됨
→ 즉, NoteA의 실제 소유자(Alice)만 이 스테이크를 처리할 수 있음
```

**현재 상태:**
```
Alice: NoteA (1 ETH, Trading)
Bob:   NoteB (100 DAI, Trading)
       StakeNote (100 DAI, Trading, 스마트노트)
Order: { ..., state: Taken }
```

---

### Phase 4: 주문 체결 (Settle Order)

주문이 원자적으로 체결됩니다.

```
1. settle_order 증명 생성
   - 입력: NoteA (메이커), StakeNote (테이커 스테이크)
   - 가격 계산 (회로 내부)
   - 출력 노트 3개 생성

2. 입력 노트 소비
   - notes[NoteA.hash] = Spent
   - notes[NoteB.hash] = Spent
   - notes[StakeNote.hash] = Spent

3. 출력 노트 생성 (모두 스마트 노트)
   - RewardNote: 1 ETH → Bob (owner = NoteB.hash에서 파생)
   - PaymentNote: 100 DAI → Alice (owner = NoteA.hash에서 파생)
   - ChangeNote: 잔돈 (이 경우 0)
```

```javascript
// 코드 예시
await orderStore.settleOrder(orderId)
```

**출력 노트의 소유자 파생:**
```
RewardNote (1 ETH → Bob):
  owner0 = NoteB.hash >> 128
  owner1 = NoteB.hash & MASK
  → Bob만 이 노트를 변환 가능

PaymentNote (100 DAI → Alice):
  owner0 = NoteA.hash >> 128
  owner1 = NoteA.hash & MASK
  → Alice만 이 노트를 변환 가능
```

**현재 상태:**
```
Alice: PaymentNote (100 DAI, Valid, 스마트노트)
Bob:   RewardNote (1 ETH, Valid, 스마트노트)
Order: { ..., state: Settled }
```

---

### Phase 5: 스마트노트 변환 (Convert)

스마트 노트를 일반 노트로 변환해야 자유롭게 사용할 수 있습니다.

#### Alice: PaymentNote 변환

```
1. convert_note 증명 생성
   - smartNote: PaymentNote
   - originNote: NoteA (부모 노트)
   - newNote: AliceDAINote (새 일반 노트)

2. PaymentNote 무효화
3. AliceDAINote 생성
```

```javascript
// 코드 예시
const aliceDAI = await noteStore.convertNote(paymentNote, aliceOriginalNote)
```

#### Bob: RewardNote 변환

```
1. convert_note 증명 생성
2. RewardNote 무효화
3. BobETHNote 생성
```

**최종 상태:**
```
Alice: AliceDAINote (100 DAI, Valid, 일반노트)
Bob:   BobETHNote (1 ETH, Valid, 일반노트)
```

---

### Phase 6: 출금 (Liquidate) - 선택

원한다면 노트를 소각하고 토큰을 출금할 수 있습니다.

```javascript
// Alice: 100 DAI 출금
await noteStore.liquidate(aliceDAI, aliceEthAddress)

// Bob: 1 ETH 출금
await noteStore.liquidate(bobETH, bobEthAddress)
```

```
│                      Phase 1: 입금                           │

│  Alice                              Bob                      │
│  1 ETH ──mint──▶ NoteA(Valid)       100 DAI ──mint──▶ NoteB  │
└──────────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────────┐
│                    Phase 2: 주문 생성                         │
├──────────────────────────────────────────────────────────────┤
│  Alice: makeOrder(NoteA, DAI, price=100)                     │

                           ↓
┌──────────────────────────────────────────────────────────────┐
│                    Phase 3: 주문 수락                         │
├──────────────────────────────────────────────────────────────┤
│  Bob: takeOrder(orderId, NoteB)                              │
│       NoteB: Valid → Trading                                 │
│       StakeNote(스마트노트, Trading) 생성                      │
│       Order(Taken)                                           │
└──────────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────────┐
│                    Phase 4: 주문 체결                         │
├──────────────────────────────────────────────────────────────┤
│  settleOrder(orderId)                                        │
│                                                              │
│  소비: NoteA, NoteB, StakeNote → Spent                       │
│                                                              │
│  생성:                                                        │
│    RewardNote(1 ETH, 스마트, Bob소유) Valid                   │
│    PaymentNote(100 DAI, 스마트, Alice소유) Valid              │
│                                                              │
│  Order(Settled)                                              │
└──────────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────────────┤
│  Alice: convertNote(PaymentNote) → AliceDAINote(일반, Valid) │
│  Bob:   convertNote(RewardNote) → BobETHNote(일반, Valid)    │
└──────────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────────┐
│                    Phase 6: 출금 (선택)                       │
├──────────────────────────────────────────────────────────────┤
│  Alice: liquidate(AliceDAINote) → 100 DAI 수령               │
│  Bob:   liquidate(BobETHNote) → 1 ETH 수령                   │
└──────────────────────────────────────────────────────────────┘
```

## 프라이버시 분석

### 공개되는 정보

| 단계 | 공개 정보 |
|------|----------|
| Mint | 금액, 토큰 종류 |
| MakeOrder | 토큰 종류, 가격 |
| TakeOrder | 토큰 종류 |
| SettleOrder | 토큰 종류, 가격 |
| Convert | 해시만 |
| Liquidate | 금액, 토큰 종류 |

### 비공개 정보

- **소유자 신원**: 누가 주문을 생성/수락했는지 알 수 없음
- **전송 내역**: Transfer는 금액/수신자 완전 비공개
- **잔액**: 각 노트의 정확한 금액 비공개 (mint/liquidate 제외)

---

## 보안 보장

### 1. 원자성 (Atomicity)
- settleOrder는 단일 트랜잭션에서 5개 노트 상태를 변경
- 부분 실행 불가능 - 증명 실패 시 전체 롤백

### 2. 이중 지불 방지
- 각 노트는 한 번만 소비 가능
- `Valid → Spent` 전이는 되돌릴 수 없음

### 3. 스마트 노트 보안
- 출력 노트의 소유자가 입력 노트 해시에서 파생
- 회로와 온체인 양쪽에서 검증
- 제3자가 노트를 가로챌 수 없음

### 4. 가치 보존
- 회로 내에서 `입력 합 == 출력 합` 검증
- 무에서 토큰 생성 불가능

---

## 에러 케이스

### 주문 취소
현재 구현에서 주문 취소 기능은 없습니다. 메이커의 노트는 체결될 때까지 잠겨 있습니다.

### 가격 불일치
테이커가 충분한 금액을 스테이크하지 않으면 체결 시 잔돈 계산에서 검증 실패합니다.

### 노트 상태 불일치
이미 소비된 노트로 작업하면 컨트랙트에서 revert됩니다.

---

## 요약

```
1. Mint: 토큰 → 노트 (금액 공개)
2. MakeOrder: 주문 생성, 노트 잠금
3. TakeOrder: 스마트 노트 생성, 스테이크
4. SettleOrder: 원자적 교환, 3개 스마트 노트 출력
5. ConvertNote: 스마트 노트 → 일반 노트
6. Liquidate: 노트 → 토큰 (금액 공개)
```

**핵심**: Transfer와 내부 거래는 완전한 프라이버시 보장,
입출금 경계에서만 금액이 공개됨.
