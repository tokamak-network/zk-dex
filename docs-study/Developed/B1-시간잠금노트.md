# B1 시간 잠금 노트 (Time-Locked Notes)

## 개요

특정 시간 이후에만 사용 가능한 프라이버시 노트 기능입니다.
- 잠금 해제 시간, 금액, 수취인 모두 비공개
- ~30K 제약 조건의 ZK 회로 (CreateTimeLock)
- ~100K 제약 조건의 ZK 회로 (SpendTimeLock)

### 핵심 유즈케이스
- **비밀 베스팅 스케줄**: 직원 토큰 부여 시 잠금 기간 설정
- **익명 유산 상속**: 특정 시점에 자동 상속
- **기밀 투자 락업**: 투자 계약의 락업 기간 구현

배포 후 브라우저를 새로고침하면 됩니다.

### "Note is still locked" 오류

Ganache의 `block.timestamp`가 아직 unlock 시간에 도달하지 않았습니다.
Ganache 시간을 조작하세요:

```bash

```

### "Note hash mismatch" 오류

노트 데이터가 손상되었거나 형식이 맞지 않습니다. 콘솔에서 자세한 로그를 확인하세요.
새 노트를 생성하고 다시 시도해보세요.

### "estimateGas" 에러 (TimeLock 생성 시)

`unlockTime`이 `block.timestamp`보다 미래가 아닐 수 있습니다.
프론트엔드가 자동으로 블록체인 시간을 확인하고 조정하지만, 시간 차이가 크면 문제가 될 수 있습니다.

## 회로 상세 설명

### CreateTimeLock 회로

**공개 입력 (4개)**:
- `noteHash`: 시간 잠금 노트 해시
- `value`: 노트 가치
- `tokenType`: 토큰 타입 (0=ETH, 1=DAI)
- `unlockTime`: 잠금 해제 Unix 타임스탬프

**비공개 입력 (3개)**:
- `pkX, pkY`: 수신자 공개키
- `salt`: 노트 무작위성

**회로 로직**:
1. 노트 해시 계산 및 검증
2. (소유권 검증 없음 - 누구나 다른 사람에게 시간 잠금 노트 생성 가능)

> **참고**: 생성 시 소유권 증명이 필요 없는 이유:
> - 자금 예치는 컨트랙트에서 검증됨 (msg.value 또는 DAI transferFrom)
> - 수신자만 (pkX/pkY의 sk를 아는 사람만) 나중에 노트를 사용할 수 있음
> - 베스팅, 상속 등의 핵심 유즈케이스를 지원

### SpendTimeLock 회로

**공개 입력 (4개)**:
- `noteHash`: 입력 시간 잠금 노트 해시
- `outputHash`: 출력 일반 노트 해시
- `currentTime`: 컨트랙트의 block.timestamp
- `tokenType`: 토큰 타입

**비공개 입력 (10개)**:
- `pkX, pkY, sk`: 소유권 정보
- `value, salt, unlockTime`: 입력 노트 정보
- `outPkX, outPkY, outSalt`: 출력 노트 정보

**회로 로직**:
1. 입력 노트 해시 검증
2. 소유권 검증 (sk → pk)
3. **시간 조건 검증**: `currentTime >= unlockTime`
4. 출력 노트 해시 계산 (일반 7-input PoseidonNote로 변환)

## 스마트 컨트랙트 함수

### createTimeLock

```solidity
function createTimeLock(
    uint256[2] calldata a,
    uint256[2][2] calldata b,
    uint256[2] calldata c,
    uint256[5] calldata input,  // [out, noteHash, value, tokenType, unlockTime]
    bytes calldata encryptedNote
) external payable;
```

- ETH: `msg.value`로 예치
- DAI: 사전 approve 후 transferFrom

### spendTimeLock

```solidity
function spendTimeLock(
    uint256[2] calldata a,
    uint256[2][2] calldata b,
    uint256[2] calldata c,
    uint256[5] calldata input,  // [out, noteHash, outputHash, currentTime, tokenType]
    bytes calldata encryptedNote
) external;
```

- 개발 모드: `currentTime`이 `block.timestamp`와 1시간 이내로 일치해야 함
- 프로덕션: `currentTime`이 `block.timestamp`와 15초 이내로 일치해야 함
- 출력 노트는 일반 노트로 생성됨 (시간 잠금 아님)

### liquidate

```solidity
function liquidate(
    address payable to,
    uint256[2] calldata a,
    uint256[2][2] calldata b,
    uint256[2] calldata c,
    uint256[4] calldata input  // [out, noteHash, value, tokenType]
) external;
```

- TimeLock에서 생성된 일반 노트를 ETH/DAI로 출금
- ZkDai.liquidate와 동일한 인터페이스

## 주의사항

### 시간 검증
- `block.timestamp`는 채굴자가 ~15초 범위 내에서 조작 가능
- 분/시간 단위 세분성 권장 (초 단위 정밀도 불필요)

### Ganache 시간 조작
- Ganache는 트랜잭션이 없으면 `block.timestamp`가 업데이트되지 않음
- 테스트 시 `evm_increaseTime` + `evm_mine` 명령 사용

### 노트 형식 호환성
- 시간 잠금 노트: 8-input Poseidon 해시
- 일반 노트: 7-input Poseidon 해시
- `lockType` 필드로 노트 타입 구분
- 지갑에서 별도 추적 필요

### 개발 모드
- `development = true`로 배포 시 증명 검증 생략
- 시간 허용 범위: 개발 모드 1시간, 프로덕션 15초
- 로컬 네트워크 (chainId 1337, 31337)에서만 허용

### 블록체인 시간 사용
- 프론트엔드에서 `Date.now()` 대신 `web3Store.getBlockTimestamp()` 사용
- 클라이언트 시간과 블록체인 시간이 다를 수 있음

## 전체 테스트 플로우 요약

```
1. TimeLock 노트 생성 (ETH/DAI 예치)
   ↓
2. 시간 경과 대기 (Ganache: evm_increaseTime 사용)
   ↓
3. Spend (TimeLock 노트 → 일반 노트로 변환)
   ↓
4. Redeem (일반 노트 → ETH/DAI 출금)
```

|------|----------|------|

| Spend | TimeLock | spendTimeLock |
