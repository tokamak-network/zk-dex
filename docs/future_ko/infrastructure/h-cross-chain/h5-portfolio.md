# H5. 멀티체인 포트폴리오

프라이버시를 보존하는 집계 및 크로스체인 리밸런싱을 통한 다중 블록체인 간 통합 포트폴리오 관리.

**요구사항**: 크로스체인 상태 검증 | 포트폴리오 commitment 스킴 | ZK 집계 증명 | 리밸런싱 인프라

---

## 배경

현대 DeFi 사용자들은 수많은 블록체인에 자산을 보유하고 있어 상당한 관리 과제를 안고 있습니다:

- **단편화된 뷰**: 각 체인의 포지션을 노출하지 않고 총 포트폴리오를 볼 수 있는 통합된 방법이 없음
- **수동 리밸런싱**: 체인 간 자산 이동이 번거롭고 비용이 많이 듦
- **프라이버시 침해**: 온체인에서 포지션을 집계하면 완전한 재무 상황이 드러남
- **세금/감사 복잡성**: 체인 간 비용 기준 및 성과 추적이 어려움

멀티체인 포트폴리오 인프라는 다음을 가능하게 합니다:
- 모든 포지션의 프라이빗 집계 뷰
- 목표 배분에 기반한 자동 크로스체인 리밸런싱
- 개별 포지션 노출 없이 통합된 리스크 지표 제공
- 완전 공개 없이 규정 준수를 위한 검증 가능한 포트폴리오 증명

ZK-DEX의 경우, 이를 통해 소매 수준의 프라이버시로 기관급 포트폴리오 관리가 가능합니다.

### 컴포넌트 목록

| 컴포넌트 | 설명 |
|-----------|-------------|
| **Position Commitment** | 각 체인의 포지션 값에 대한 ZK commitment |
| **Cross-Chain Oracle** | 다른 체인의 포지션 commitment를 검증 |
| **Aggregation Circuit** | 개별 금액을 드러내지 않고 포지션 값을 합산 |
| **Rebalancer** | 목표 배분에 맞게 크로스체인 전송 실행 |
| **Risk Calculator** | 포트폴리오 지표를 비공개로 계산 |
| **Audit Proof Generator** | 규정 준수를 위한 선택적 공개 증명 생성 |

### 데이터 플로우

1. **Position Commitment 플로우**
   - 각 체인의 사용자 포지션이 ZK 증명과 함께 commit됨
   - Commitment에는 값, 자산 유형, 타임스탬프 포함
   - Commitment가 aggregator에 제출됨

2. **집계 플로우**
   - Aggregator가 모든 체인에서 commitment를 수집
   - 세부 내역을 드러내지 않고 총액을 증명하는 ZK 증명 생성
   - 사용자는 통합된 포트폴리오 뷰를 비공개로 확인

3. **리밸런싱 플로우**
   - 사용자가 목표 배분 설정 (예: 40% ETH, 30% BTC, 30% 스테이블코인)
   - Aggregator가 현재 vs. 목표를 비공개로 비교
   - 체인 간 리밸런싱 트랜잭션 실행
   - 모든 이동이 숨겨짐; 순 포지션만 표시됨

### 포트폴리오 집계 회로

```circom
pragma circom 2.1.0;

include "../utils/poseidon/poseidon.circom";
include "../utils/comparators.circom";

template PortfolioAggregate(numChains) {
    // Public inputs
    signal input portfolioCommitment;    // Commitment to total portfolio
    signal input chainCommitments[numChains]; // Per-chain commitments
    signal input timestamp;

    // Private inputs
    signal input values[numChains];      // Position values per chain
    signal input salts[numChains];       // Commitment randomness
    signal input portfolioSalt;

    // Verify each chain commitment
    component chainHash[numChains];
    for (var i = 0; i < numChains; i++) {
        chainHash[i] = Poseidon(2);
        chainHash[i].inputs[0] <== values[i];
        chainHash[i].inputs[1] <== salts[i];
        chainHash[i].out === chainCommitments[i];
    }

    // Compute total value
    signal totalValue;
    signal runningSum[numChains + 1];
    runningSum[0] <== 0;
    for (var i = 0; i < numChains; i++) {
        runningSum[i + 1] <== runningSum[i] + values[i];
    }
    totalValue <== runningSum[numChains];

    // Verify portfolio commitment
    component portHash = Poseidon(3);
    portHash.inputs[0] <== totalValue;
    portHash.inputs[1] <== portfolioSalt;
    portHash.inputs[2] <== timestamp;
    portHash.out === portfolioCommitment;
}

component main {public [portfolioCommitment, chainCommitments, timestamp]} = PortfolioAggregate(5);
```

## 효과

| 측면 | 영향 |
|--------|--------|
| **통합된 뷰** | 모든 크로스체인 포지션을 위한 단일 대시보드 |
| **포지션 프라이버시** | 개별 체인 포지션 숨김; 집계만 표시 |
| **자동화된 관리** | 수동 크로스체인 트랜잭션 없이 리밸런싱 |
| **리스크 가시성** | 노출 없이 포트폴리오 수준 리스크 지표 제공 |
| **규정 준수 준비** | 완전 공개 없이 감사자를 위한 선택적 증명 |
| **자본 효율성** | 기회에 기반한 체인 간 최적 배분 |

## 보안 고려사항

| 리스크 | 완화 |
|------|------------|
| **오래된 포지션 데이터** | 타임스탬프 검증; freshness 증명 |
| **크로스체인 오라클 조작** | 다중 오라클 소스; ZK light client |
| **리밸런싱 프론트러닝** | 암호화된 리밸런싱 의도; commit-reveal |
| **Commitment Grinding** | Salt에 충분한 무작위성 |
| **프라이버시 상관관계** | 타이밍 난독화; 일괄 업데이트 |
| **무단 리밸런싱** | 실행을 위한 다중 서명 또는 임계값 서명 |

## 구현 과제

1. **크로스체인 상태 동기화**
   - 포지션이 체인 간에 지속적으로 변경됨
   - 스냅샷 타이밍이 조정되어야 함
   - 체크포인트 기반 검증 사용 고려

2. **자산 가격 정규화**
   - 다른 체인은 다른 가격을 가질 수 있음
   - 집계를 위한 표준 가격 소스 필요
   - 일관성을 위한 USD 또는 ETH 표시

3. **가스 비용 분배**
   - 리밸런싱은 여러 체인에서 가스를 발생시킴
   - 작업 간 공정한 비용 할당
   - 가스 추상화 서비스 고려

4. **포트폴리오 뷰의 지연**
   - 크로스체인 commitment 수집에 시간이 소요됨
   - 실시간 뷰가 실제 포지션에서 지연될 수 있음
   - 허용 가능한 staleness 매개변수 필요

5. **복잡한 자산 유형**
   - LP 포지션, 스테이킹된 자산, 베스팅 토큰
   - 평가에 특화된 오라클 필요
   - 양도 불가능한 포지션은 리밸런싱 불가

## 파생

1. **크로스체인 리밸런싱** - 목표 배분을 유지하기 위한 자동 포트폴리오 조정. 편차가 임계값을 초과할 때 트리거됨. 브리지와 DEX를 통한 최적 라우팅 사용.

2. **통합 회계** - 세금 및 보고를 위한 모든 체인 간 일관된 회계. 각 포지션에 대한 비용 기준 추적. 자동화된 세금 로트 선택 최적화.

3. **멀티체인 수익률** - 모든 체인의 집계된 수익률 계산. 다양한 배분의 기회비용 비교. 수익률 최적화 이동을 비공개로 제안.

4. **리스크 집계** - 포트폴리오 수준 VaR, 상관관계 및 노출 지표. 개별 포지션 숨김; 집계된 리스크 표시. 기관 리스크 관리에 유용.

5. **세금 보고** - 전체 이력을 드러내지 않고 규정을 준수하는 세금 보고서 생성. 선택적 공개를 통한 손익 증명. 다중 관할권 요구사항 지원.

## 사용 사례

1. **기관 포트폴리오 관리**
   - 펀드가 5개 체인에 포지션 보유
   - 통합 뷰는 총 AUM을 비공개로 표시
   - 위원회 결정에 기반한 리밸런싱 실행
   - 감사자가 전략을 보지 않고 보유자산 검증

2. **개인 자산 대시보드**
   - 개인이 모든 암호화폐 보유자산 추적
   - DeFi 프로토콜 간 단일 인터페이스
   - 목표 배분에 대한 자동 리밸런싱
   - 프라이버시 유지; 단일 체인에서 전체 그림 드러나지 않음

3. **크로스체인 수익률 최적화**
   - 사용자가 여러 체인에 스테이블코인 보유
   - 포트폴리오 추적기가 최고 수익률 식별
   - 최적 장소로 자금을 자동으로 이동
   - 모든 이동이 비공개; 전략 숨김

4. **규정 준수 보고**
   - 규제 대상 기관이 분기별 보고 필요
   - 임계값 이상의 보유자산에 대한 ZK 증명 생성
   - 구성을 보여주지 않고 총액만 공개
   - 최소 공개로 규제 요구사항 충족

## 실제 제품 및 사용자 경험

### 1. "총 자산 숨기기" - 전체 포트폴리오 규모 비공개

**제품 설명**:
여러 체인에 분산된 자산을 관리하면서 전체 포트폴리오 규모가 추론되지 않도록 보호하는 서비스. 각 체인 자산을 연결하면 총자산이 노출됩니다.

**일반 사용자 경험**:
- 강민준씨(32세)는 5개 체인에 총 $500,000 분산 보유
- 일반 관리: 각 체인 잔액을 더하면 전체 자산 파악됨
- 프라이빗 관리: 각 체인의 commitment만 집계, 금액은 숨김
- 민준씨 본인만 "$500K 보유" 확인 가능
- 외부 분석가는 "이 5개 지갑이 같은 사람인지"도 모름

**관찰 가능한 이점**:
- 멀티체인 자산 연결 분석 방지
- 전체 순자산 규모 비공개
- "고액 자산가" 타겟팅 공격 방지

### 2. "비밀 리밸런싱" - 포트폴리오 조정 패턴 숨김

**제품 설명**:
포트폴리오 리밸런싱 시 어떤 자산을 얼마나 조정했는지가 외부에 노출되지 않는 프라이빗 리밸런싱 서비스.

**일반 사용자 경험**:
- 박지영씨(38세)는 ETH 비중이 높아져 BTC로 리밸런싱 필요
- 일반 리밸런싱: "$100K ETH 매도, $100K BTC 매수" 패턴 공개
- 비밀 리밸런싱: 여러 체인에서 동시에 비공개로 조정
- 외부에서는 어떤 조정이 일어났는지 알 수 없음
- 리밸런싱 의도(약세 전환?)가 시장에 노출되지 않음

**관찰 가능한 이점**:
- 투자 전략 변경이 비공개
- 리밸런싱이 시장 신호가 되지 않음
- 대량 리밸런싱의 시장 영향 최소화

### 3. "증명 가능한 잔액" - 선택적 공개 자산 증명

**제품 설명**:
전체 포트폴리오를 공개하지 않고 "X 이상 보유"만 증명할 수 있는 선택적 공개 서비스. 대출, 투자 자격 등에 활용됩니다.

**일반 사용자 경험 (기관 관점)**:
- XYZ 펀드는 투자자에게 "AUM $100M 이상" 증명 필요
- 일반 증명: 전체 포지션 공개 → 경쟁사에 전략 노출
- 선택적 증명: "총 자산 ≥ $100M" ZK 증명만 제공
- 구체적으로 어디에 얼마 투자했는지는 비공개
- 투자자는 안심, 경쟁사는 전략 파악 불가

**관찰 가능한 이점**:
- 자격 증명 시 최소 정보만 공개
- 포트폴리오 구성이 영업 비밀로 보호
- 규제/감사 요구에 과도한 공개 없이 대응
