# I8. 홀로그래픽 합의

중요한 결정에 대한 관심과 참여를 높이기 위해 제안 결과에 대한 스테이크된 예측을 사용하는 거버넌스 메커니즘.

**요구사항**: 예측 스테이킹 | 관심 신호 | 부스팅 메커니즘 | 평판 추적

---

## 배경

DAO 거버넌스는 만성적으로 낮은 참여율을 겪습니다:

- **투표자 피로**: 너무 많은 제안; 충분하지 않은 관심
- **정보 비대칭**: 대부분의 투표자가 기술적 세부사항에 무지함
- **낮은 스테이크**: 개별 투표가 거의 결정적이지 않음
- **플루토크라시 우려**: 대형 홀더가 불균형적으로 영향력 있음

홀로그래픽 합의는 다음을 통해 이를 해결합니다:
- 예측 스테이크를 사용하여 제안 중요성 신호
- 통과 예측되는 제안에 관심 부스팅
- 거버넌스 참여를 위한 금융 인센티브 생성
- 소액 이해관계자가 중요한 이슈를 확대할 수 있게 함

ZK-DEX의 경우, 이것은 중요한 거버넌스 결정이 적절한 관심을 받도록 보장합니다.

### 구성 요소 목록

| 구성 요소 | 설명 |
|-----------|-------------|
| **Prediction Pool** | 제안 결과를 예측하는 스테이크 수집 |
| **Boost Calculator** | 제안이 부스트 임계값에 도달했는지 결정 |
| **Reputation System** | 시간 경과에 따른 예측자 정확도 추적 |
| **Attention Signal** | 부스트된 제안을 눈에 띄게 표시 |
| **Settlement Engine** | 실제 결과에 따라 스테이크 분배 |
| **Governance Adapter** | 홀로그래픽 레이어를 투표에 연결 |

### 데이터 흐름

1. **예측 단계**
   - 제안이 거버넌스에 제출됨
   - 예측자가 예상 결과(통과/실패)에 스테이크
   - 예측 풀에 스테이크 누적

2. **부스트 평가**
   - YES 스테이크가 임계값을 초과하면 제안 부스트
   - 부스트된 제안은 신속한 투표 진행
   - 부스트된 제안에 대한 더 낮은 정족수 요구사항

3. **정산**
   - 투표 종료 후 결과 알려짐
   - 올바른 예측자가 패배자의 스테이크 수령
   - 정확도에 따라 평판 업데이트

### 홀로그래픽 스테이킹 회로

```circom
pragma circom 2.1.0;

include "../utils/poseidon/poseidon.circom";
include "../utils/comparators.circom";

template HolographicStake() {
    // Public inputs
    signal input proposalId;          // Which proposal
    signal input stakeCommitment;     // Commitment to stake
    signal input prediction;          // 1 = YES, 0 = NO (public for aggregation)
    signal input nullifier;

    // Private inputs
    signal input amount;              // Stake amount (hidden)
    signal input staker;              // Staker identity (hidden)
    signal input reputation;          // Current reputation score
    signal input salt;

    // Verify stake commitment
    component stakeHash = Poseidon(5);
    stakeHash.inputs[0] <== proposalId;
    stakeHash.inputs[1] <== amount;
    stakeHash.inputs[2] <== prediction;
    stakeHash.inputs[3] <== staker;
    stakeHash.inputs[4] <== salt;
    stakeHash.out === stakeCommitment;

    // Verify prediction is valid (0 or 1)
    prediction * (1 - prediction) === 0;

    // Verify minimum stake based on reputation
    // Higher reputation allows smaller minimum stakes
    component minStake = LessThan(64);
    signal minRequired;
    minRequired <== 1000 - reputation * 10;  // Simplified
    minStake.in[0] <== minRequired;
    minStake.in[1] <== amount + 1;
    minStake.out === 1;
}

component main {public [proposalId, stakeCommitment, prediction, nullifier]} = HolographicStake();
```

## 구현 과제

1. **부스트 임계값 조정**
   - 너무 낮음: 모든 것이 부스트됨; 목적 상실
   - 너무 높음: 중요한 제안이 관심을 받지 못함
   - 활동에 따른 적응형 임계값 필요

2. **예측 정확도 인센티브**
   - 정확한 예측에 보상해야 함
   - 명백한 예측에 보상하는 것 피해야 함
   - 신뢰도 가중 보상 고려

3. **정족수 요구사항**
   - 부스트된 제안은 더 낮은 정족수 필요
   - 얼마나 낮은 것이 안전한가?
   - 효율성 vs. 보안 균형

4. **스테이크 잠금**
   - 제안이 해결될 때까지 스테이크 잠금
   - 긴 제안은 자본을 묶어둠
   - 유동성을 위한 스테이크 시장 고려

5. **투표와의 통합**
   - 홀로그래픽 레이어가 기존 거버넌스와 통합되어야 함
   - 현재 제안과의 하위 호환성
   - 예측과 투표 단계 간 명확한 전환

## 파생물

1. **Attention Mining** - 중요한 제안을 표면화하는 것에 대한 보상. 스테이커가 평판과 토큰 획득. 거버넌스 관심을 위한 시장 생성.

2. **Prediction Staking** - 예상 거버넌스 결과에 토큰 스테이크. 올바른 예측은 수익 획득. 잘못된 예측은 스테이크 손실.

3. **Consensus Boosting** - 충분한 긍정적 스테이크가 있는 제안은 부스트됨. 더 낮은 정족수와 더 빠른 투표. 합의 제안의 효율적 처리.

4. **Signal Aggregation** - 부스트 결정을 위한 여러 약한 신호 결합. 스테이크 금액, 예측자 평판, 커뮤니티 감정. 견고한 부스트 기준.

5. **Reputation Systems** - 시간 경과에 따른 예측자 정확도 추적. 더 높은 평판 = 더 낮은 스테이크 요구사항. 거버넌스에 대한 실력주의적 영향.

## 사용 사례

1. **긴급 보안 수정**
   - 중요한 취약점 발견
   - 보안 연구자가 YES에 많이 스테이크
   - 제안이 즉시 부스트됨
   - 신속 투표로 빠른 수정 가능

2. **논란 있는 제안 필터링**
   - 분열적인 제안 제출
   - 예측이 50/50으로 분할
   - 부스트되지 않음; 전체 정족수 필요
   - 논란 있는 결정은 완전한 심의 진행

3. **기술 업그레이드**
   - 일상적인 기술 개선 제안
   - 전문가가 YES에 스테이크; 중요한 NO 스테이크 없음
   - 신속 승인을 위해 부스트됨
   - 논란 없는 업그레이드의 효율적 처리

4. **커뮤니티 제안 확대**
   - 소액 이해관계자가 중요한 이슈 식별
   - 전체 보유량을 YES 예측에 스테이크
   - 더 큰 홀더가 스테이크 추가하여 제안 부스트
   - 작은 보유에도 불구하고 커뮤니티 목소리 증폭

## 실제 제품 및 사용자 경험

### 1. "비밀 스테이킹" - 예측 스테이킹 금액 숨김

**제품 설명**:
홀로그래픽 스테이킹 시 "누가 얼마를 스테이킹했는지"가 공개되지 않아 대형 홀더의 영향력이 사전에 노출되지 않는 시스템.

**일반 사용자 경험**:
- 제안에 대해 스테이킹하려는 참여자
- 일반 시스템: "대형 홀더가 $1M 스테이킹" → 군중 따라함
- 비밀 스테이킹: 스테이킹 금액이 commitment로 숨겨짐
- "누군가 스테이킹했다"만 알고 금액은 모름
- 부스트 임계값 도달 여부만 공개
- 각자 독립적인 판단으로 참여

**관찰 가능한 이점**:
- 대형 홀더 행동 따라하기 방지
- 독립적인 의사결정 유도
- 스테이킹 금액으로 영향력 추정 차단

### 2. "익명 부스팅" - 누가 부스트했는지 숨김

**제품 설명**:
제안을 부스트하기 위해 스테이킹한 사람의 신원이 공개되지 않아 정치적 보복 없이 중요한 제안을 지지할 수 있는 시스템.

**일반 사용자 경험**:
- 이소액씨가 민감한 제안(팀 교체)을 부스트하고 싶음
- 일반 부스팅: "이소액씨가 팀 교체 제안 부스트" → 팀과 갈등
- 익명 부스팅: 스테이킹 참여자 신원이 숨겨짐
- 팀은 "누군가 이 제안을 부스트함"만 알고 누군지 모름
- 보복 두려움 없이 필요한 제안 지지 가능

**관찰 가능한 이점**:
- 민감한 제안도 자유롭게 부스트 가능
- 정치적 보복 위험 제거
- 필요한 변화에 대한 솔직한 지지

### 3. "명성 프라이버시" - 예측 이력 선택적 공개

**제품 설명**:
예측 명성 점수가 있지만 "구체적으로 어떤 예측을 했는지"는 숨길 수 있어 전략이 노출되지 않는 명성 시스템.

**일반 사용자 경험**:
- 김전문가는 85점의 높은 명성 점수 보유
- 일반 명성: "김씨는 보수적 제안에 항상 반대" 패턴 노출
- 프라이버시 명성: "85점" 점수만 공개, 세부 이력은 비공개
- 다른 사람이 김씨의 투표 패턴을 분석할 수 없음
- 김씨의 판단 성향이 비공개로 보호됨

**관찰 가능한 이점**:
- 예측 전략 패턴 분석 방지
- 명성은 증명하면서 성향은 숨김
- "이 사람 따라하기" 전략 차단
