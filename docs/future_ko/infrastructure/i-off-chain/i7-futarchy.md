# I7. 퓨타키 시장

시장 가격이 프로토콜 결정에 정보를 제공하면서 투표자 프라이버시를 유지하는 예측 시장 기반 거버넌스 인프라.

**요구사항**: 조건부 토큰 프레임워크 | 시장 조성 | 결정 오라클 | 프라이빗 투표 통합

---

## 배경

전통적인 거버넌스는 상당한 한계를 겪습니다:

- **정보 집계**: 토큰 투표는 지식을 효율적으로 집계하지 못함
- **투표자 무관심**: 거버넌스 투표에 낮은 참여율
- **플루토크라시**: 대형 홀더가 전문성과 관계없이 결정 지배
- **게이밍**: 투표 매수와 전략적 투표가 결과 왜곡

퓨타키는 예측 시장을 사용하여 이를 해결합니다:
- 시장은 분산된 정보를 효율적으로 집계
- 금융 인센티브가 정보에 기반한 참여자를 유인
- 누구나 확신에 비례하여 결과에 영향을 줄 수 있음
- 시장 조작은 비용이 많이 들고 자기 교정됨

ZK-DEX의 경우, 퓨타키는 프라이버시가 보존된 참여와 함께 증거 기반 거버넌스를 가능하게 합니다.

## 기술 사양

### 아키텍처 개요

```
Proposal                      Futarchy Markets                   Decision
+------------+                +-----------------------+          +----------+
|            |                |                       |          |          |
| Governance |  Create        |  Conditional Market A |          | Execute  |
| Proposal   |--------------->|  "Price if YES"       |--------->| or       |
|            |                |                       |          | Reject   |
+------------+                |  Conditional Market B |          +----------+
                              |  "Price if NO"        |
                              |                       |
                              +-----------------------+
                                       |
                                       v
                              +-----------------------+
                              |  Price Comparison     |
                              |  YES price > NO price |
                              |  = Execute proposal   |
                              +-----------------------+
```

### 구성 요소 목록

| 구성 요소 | 설명 |
|-----------|-------------|
| **Proposal Contract** | 결정을 정의하고 시장 생성 |
| **Conditional Tokens** | 결정 결과에 따라 정산되는 토큰 |
| **Market Maker** | 가격 발견을 위한 유동성 제공 |
| **Price Oracle** | 최종 정산 가격 결정 |
| **Decision Engine** | 시장 합의에 따라 실행 |
| **Privacy Layer** | 프라이빗 시장 참여를 위한 ZK 증명 |

### 데이터 흐름

1. **제안 생성**
   - 거버넌스 제안 제출
   - 두 개의 조건부 시장 생성:
     - 시장 A: 제안 통과 가정 시 토큰 가격
     - 시장 B: 제안 실패 가정 시 토큰 가격

2. **시장 거래**
   - 참여자가 믿음에 따라 거래
   - 정보에 기반한 트레이더는 이익; 그렇지 않으면 손실
   - 가격이 진정한 예상 가치로 수렴

3. **결정 실행**
   - 거래 기간 후 가격 비교
   - Price(YES) > Price(NO)인 경우: 제안 실행
   - 그에 따라 시장 정산

### 퓨타키 시장 회로

```circom
pragma circom 2.1.0;

include "../utils/poseidon/poseidon.circom";
include "../utils/comparators.circom";

template FutarchyTrade() {
    // Public inputs
    signal input marketId;           // Which market (YES or NO)
    signal input tradeCommitment;    // Commitment to trade details
    signal input priceCommitment;    // Commitment to execution price
    signal input nullifier;

    // Private inputs
    signal input trader;             // Trader identity (hidden)
    signal input amount;             // Trade size (hidden)
    signal input price;              // Execution price
    signal input direction;          // Buy(1) or Sell(0)
    signal input salt;

    // Verify trade commitment
    component tradeHash = Poseidon(5);
    tradeHash.inputs[0] <== marketId;
    tradeHash.inputs[1] <== trader;
    tradeHash.inputs[2] <== amount;
    tradeHash.inputs[3] <== direction;
    tradeHash.inputs[4] <== salt;
    tradeHash.out === tradeCommitment;

    // Verify price commitment
    component priceHash = Poseidon(3);
    priceHash.inputs[0] <== price;
    priceHash.inputs[1] <== marketId;
    priceHash.inputs[2] <== salt;
    priceHash.out === priceCommitment;

    // Verify direction is valid
    direction * (1 - direction) === 0;
}

component main {public [marketId, tradeCommitment, priceCommitment, nullifier]} = FutarchyTrade();
```

## 영향

| 측면 | 영향 |
|--------|--------|
| **정보 품질** | 시장은 투표보다 지식을 더 잘 집계 |
| **참여** | 금융 인센티브가 참여 증가 |
| **조작 저항성** | 조작은 비용이 많이 듦; 시장은 자기 교정 |
| **결정 품질** | 증거 기반 결정; 책임감 있는 참여 |
| **투표자 프라이버시** | ZK 증명이 개별 포지션 숨김 |
| **전문성 가중치** | 지식 있는 참여자가 자연스럽게 가중됨 |

## 보안 고려사항

| 위험 | 완화 |
|------|------------|
| **시장 조작** | 조작 비용이 이익을 초과 |
| **얇은 시장** | 최소 유동성 요구사항; 보조금 지원 시장 조성 |
| **오라클 조작** | 탈중앙화 오라클 네트워크; TWAP 가격 |
| **제안 스팸** | 제안 보증금; 큐레이션 시장 |
| **단기적 사고** | 긴 평가 기간; 지연된 정산 |
| **담합** | 프라이빗 거래; 예측 불가능한 매칭 |

## 구현 과제

1. **유동성 부트스트래핑**
   - 새로운 시장은 유동성이 낮음
   - 넓은 스프레드가 참여 저해
   - 초기에 시장 조성자 보조금 필요

2. **결정 지표 정의**
   - 어떤 가격이 "성공"을 측정하는가?
   - 프로토콜 토큰 가격? TVL? 사용자 수?
   - 시장 명확성을 위해 명확한 지표 필수

3. **시간 범위**
   - 짧은 시장은 장기 가치를 반영하지 못할 수 있음
   - 긴 시장은 자본을 묶어둠
   - 최적 기간은 결정 유형에 따라 다름

4. **조건부 정산**
   - 시장은 승리 시나리오에 대해서만 정산
   - 패배 시나리오 토큰은 가치 없음
   - 명확한 정산 규칙 필요

5. **재귀성**
   - 시장 결과가 결정에 영향을 주고 결정이 시장에 영향을 줌
   - 불안정한 피드백 루프 생성 가능
   - 신중한 메커니즘 설계 필요

## 파생물

1. **Conditional Markets** - 제안 결과에 따라 지급되는 토큰. YES 토큰은 제안 통과 시 지급. NO 토큰은 제안 실패 시 지급.

2. **Policy Markets** - 특정 정책의 결과 예측. 대안의 예상 결과 비교. 데이터 기반 정책 선택.

3. **Information Markets** - 검증 가능한 미래 사실에 대한 시장. 정보 공개 인센티브화. 결정 시장과 연결.

4. **Decision Markets** - 거버넌스 결정을 위한 특화 시장. 제안을 위한 표준화된 프레임워크. 결과에 따른 자동 실행.

5. **Meta-Governance Markets** - 거버넌스 프로세스 자체에 대한 시장. 퓨타키를 사용해야 할까? 자기 참조적 개선.

## 사용 사례

1. **프로토콜 매개변수 변경**
   - 제안: 수수료를 0.3%에서 0.5%로 증가
   - 시장은 각 시나리오에서 프로토콜 토큰 가격 예측
   - 더 높은 예상 가격이 승리
   - 데이터 기반 수수료 최적화

2. **재무 배분**
   - 제안: 마케팅 vs. 개발에 $1M 지출
   - 시장은 프로토콜 지표에 대한 영향 예측
   - 예측된 ROI에 따라 배분
   - 정보에 기반한 자본 배치

3. **파트너십 결정**
   - 제안: 프로토콜 X와 통합
   - 시장은 통합의 가치 예측
   - 현상 유지 예측과 비교
   - 증거 기반 파트너십 선택

4. **긴급 대응**
   - 보안 취약점 발견
   - 시장이 전문가 의견을 빠르게 집계
   - 정보에 기반한 참여자와 함께 빠른 결정
   - 시장 검증과 함께 신속한 대응

## 실제 제품 및 사용자 경험

### 1. "비밀 베팅 거버넌스" - 예측 포지션 완전 비공개

**제품 설명**:
예측시장에서 참여자의 베팅 포지션(어느 쪽에 얼마나)이 공개되지 않아 사회적 압력 없이 진정한 예측을 할 수 있는 프라이버시 거버넌스.

**일반 사용자 경험**:
- DAO에서 "수수료 인상" 제안 예측시장 진행
- 일반 시장: "대형 홀더가 인상에 베팅" → 다른 사람 따라함
- 비밀 베팅: 모든 베팅이 commitment로 숨겨짐
- 참여자들은 대형 홀더의 포지션을 알 수 없음
- 각자 독립적인 판단으로 베팅
- 집계 시에만 전체 결과 공개

**관찰 가능한 이점**:
- 대형 홀더 베팅에 따른 군중심리 차단
- 독립적이고 정직한 예측 유도
- 진정한 집단지성 반영

### 2. "예측 프라이버시" - 누가 맞았는지 숨김

**제품 설명**:
예측이 맞았을 때 "누가 맞았고 얼마 벌었는지"가 공개되지 않아 예측 능력이 있는 사람이 타겟이 되지 않는 서비스.

**일반 사용자 경험 (프로토콜 운영자 관점)**:
- 예측시장에서 일관되게 높은 적중률을 기록
- 일반 시장: "이 주소가 항상 맞는다" → 다른 사람이 따라함
- 프라이버시 시장: 적중 여부와 수익이 개인별로 숨겨짐
- "정보통"이 누군지 외부에서 알 수 없음
- 예측 능력이 있는 참여자의 지속적인 알파 보호

**관찰 가능한 이점**:
- 정보 우위자의 프라이버시 보호
- "따라하기" 전략으로 알파 훼손 방지
- 지식 있는 참여자의 지속적 참여 유인

### 3. "익명 정책 평가" - 평가자 신원 보호

**제품 설명**:
프로토콜 정책에 대한 예측 평가에 참여할 때 "누가 어떤 평가를 했는지" 완전히 숨겨져 정치적 보복 없이 솔직한 평가가 가능한 시스템.

**일반 사용자 경험**:
- DAO 핵심 멤버가 새 정책에 회의적이지만 공개 반대는 부담
- 일반 평가: "핵심 멤버가 반대 베팅" → 정치적 갈등
- 익명 평가: 베팅 내역이 신원과 분리됨
- "누군가 반대에 베팅했다"만 알고 누구인지 모름
- 솔직한 평가가 가능해져 더 나은 의사결정

**관찰 가능한 이점**:
- 내부 정치에서 자유로운 평가
- 솔직한 의견 표현 가능
- 보복 두려움 없이 소신 예측
