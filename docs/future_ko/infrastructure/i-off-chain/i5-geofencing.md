# I5. 지오펜싱

정확한 사용자 위치를 노출하지 않고 관할권 기반 접근 제어를 가능하게 하는 프라이버시 보존 지리적 규정 준수 인프라.

**요구사항**: 위치 증명 | ZK 위치 증명 | 관할권 매핑 | 규정 준수 오라클 네트워크

---

## 배경

DeFi 프로토콜은 지리적 제한과 관련하여 증가하는 규제 압력에 직면합니다:

- **규제 요구사항**: 많은 관할권이 특정 사용자 차단 요구
- **제재 준수**: OFAC 및 유사 목록이 지리적 스크리닝 의무화
- **라이선스 제한**: 일부 서비스는 특정 지역에서만 라이선스됨
- **프라이버시 우려**: 전통적인 지오펜싱은 정확한 사용자 위치 노출

프라이버시 보존 지오펜싱은 다음을 통해 이를 해결합니다:
- 정확한 위치를 공개하지 않고 관할권 멤버십 증명
- 중앙화된 위치 데이터베이스 없이 규정 준수 가능
- 동적 증명으로 여행 중인 사용자 지원
- 규제 준수와 사용자 프라이버시 균형

ZK-DEX의 경우, 이는 사용자 프라이버시를 보존하면서 규제 준수 운영을 가능하게 합니다.

## 기술 사양

### 아키텍처 개요

```
사용자 디바이스                증명 계층                      ZK-DEX
+------------+                +------------------------+         +-----------+
|            |  위치          |                        |         |           |
| GPS/IP     |  클레임        |  증명 오라클 1         |         | 접근      |
| 데이터     |--------------->|  증명 오라클 2         |-------->| 제어      |
|            |                |  증명 오라클 3         |         | 컨트랙트  |
+------------+                |         |              |         |           |
      |                       |         v              |         +-----------+
      |                       |  +----------------+    |              |
      v                       |  | 위치           |    |              v
+------------+                |  | 집계자         |    |         +-----------+
| 위치       |                |  +----------------+    |         | 허용      |
| 증명       |                |         |              |         | 관할권    |
| 생성기     |--------------->|         v              |         | 목록      |
+------------+   ZK 증명      |  관할권 증명           |         +-----------+
                              |  (지역, 정확하지 않음) |
                              +------------------------+
```

### 컴포넌트 목록

| 컴포넌트 | 설명 |
|-----------|-------------|
| **위치 증명자** | 사용자 위치를 증명하는 신뢰할 수 있는 오라클 |
| **증명 생성기** | 관할권 멤버십의 ZK 증명 생성 |
| **관할권 매퍼** | 좌표를 규제 지역으로 매핑 |
| **규정 준수 컨트랙트** | 관할권 증명에 따라 접근 집행 |
| **업데이트 서비스** | 규정 변경 및 사용자 여행 처리 |
| **감사 추적** | 프라이버시 보존 규정 준수 기록 |

### 데이터 흐름

1. **증명 흐름**
   - 사용자의 디바이스가 위치 데이터 제공 (GPS, IP 등)
   - 여러 증명 오라클이 위치 검증
   - 대략적인 지역에 대한 임계값 합의

2. **증명 생성**
   - 위치가 규제 지역으로 증명됨 (정확한 좌표 아님)
   - ZK 증명 생성: "사용자가 허용된 관할권에 있음"
   - 증명을 접근 제어 컨트랙트에 제출

3. **접근 제어**
   - 컨트랙트가 ZK 증명 유효성 검증
   - 허용 목록에 대해 관할권 확인
   - 그에 따라 접근 허용 또는 거부

### 지오펜스 증명 회로

```circom
pragma circom 2.1.0;

include "../utils/poseidon/poseidon.circom";
include "../utils/comparators.circom";

template GeofenceProof(numOracles) {
    // 공개 입력
    signal input jurisdictionCommitment;  // 관할권에 대한 커밋먼트
    signal input userCommitment;          // 숨겨진 사용자 신원
    signal input timestamp;               // 신선도
    signal input allowedJurisdictions[10]; // 허용된 지역 목록

    // 비공개 입력
    signal input jurisdiction;            // 사용자의 실제 관할권
    signal input userPk;                  // 사용자 공개키
    signal input oracleAttestations[numOracles]; // 오라클 서명
    signal input salt;

    // 관할권 커밋먼트 검증
    component jurisHash = Poseidon(3);
    jurisHash.inputs[0] <== jurisdiction;
    jurisHash.inputs[1] <== timestamp;
    jurisHash.inputs[2] <== salt;
    jurisHash.out === jurisdictionCommitment;

    // 사용자 커밋먼트 검증
    component userHash = Poseidon(2);
    userHash.inputs[0] <== userPk;
    userHash.inputs[1] <== salt;
    userHash.out === userCommitment;

    // 관할권이 허용 목록에 있는지 확인
    signal isAllowed[10];
    signal anyAllowed;
    signal allowedSum[11];
    allowedSum[0] <== 0;

    for (var i = 0; i < 10; i++) {
        component eq = IsEqual();
        eq.in[0] <== jurisdiction;
        eq.in[1] <== allowedJurisdictions[i];
        isAllowed[i] <== eq.out;
        allowedSum[i + 1] <== allowedSum[i] + isAllowed[i];
    }

    // 최소 하나의 일치 필요
    component allowed = GreaterThan(8);
    allowed.in[0] <== allowedSum[10];
    allowed.in[1] <== 0;
    allowed.out === 1;
}

component main {public [jurisdictionCommitment, userCommitment, timestamp, allowedJurisdictions]} = GeofenceProof(3);
```

## 효과

| 측면 | 영향 |

| **프라이버시** | 정확한 위치는 절대 공개 안 됨; 지역 멤버십만 |
| **사용자 경험** | 허용된 관할권에서 원활한 접근 |
| **유연성** | 프로토콜 변경 없이 규정 업데이트 가능 |
| **감사 가능성** | 사용자 데이터 노출 없이 규정 준수 증명 가능 |
| **분산화** | 여러 증명자가 단일 장애 지점 방지 |

| **프라이버시 상관관계** | 타이밍 난독화; 배치 증명 |

## 구현 과제

1. **정확한 위치 결정**
   - GPS는 위조될 수 있음
   - IP 지리 위치는 부정확함
   - 여러 확증 신호 필요

2. **모바일 사용자 처리**
   - 사용자가 관할권을 넘나듦
   - 효율적인 재증명 필요
   - 유효 기간 고려

3. **규제 복잡성**
   - 관할권마다 다른 요구사항
   - 규정이 자주 변경됨
   - 유연한 규정 준수 규칙 필요

4. **오라클 신뢰**
   - 위치 오라클이 상당한 권한 보유
   - 분산 오라클 네트워크 필요
   - 평판 시스템 고려

5. **경계 사례**
   - 국경 근처 사용자
   - 공해/영공
   - 분쟁 영토

## 파생상품

1. **다중 구역 규정 준수** - 관할권당 다른 규칙 지원. EU 대 미국 대 아시아 요구사항. 자동 규정 준수 전환.

2. **여행 사용자** - 모바일 사용자를 위한 원활한 재증명. 관할권 변경 시 신속한 증명 업데이트. 서비스 중단 없음.

3. **VPN 탐지** - VPN 사용을 적절히 식별하고 처리. 차단하거나 추가 검증 요구. 구성 가능한 정책.

4. **관할권 차익거래** - 유리한 규정을 찾는 사용자. 관할권 쇼핑 탐지. 냉각 기간 구현.

5. **위치 증명** - 재사용 가능한 위치 자격증명. 프로토콜 간 이식 가능. 시간 제한 유효성.

## 사용 사례

1. **미국 제재 준수**
   - 프로토콜이 OFAC 목록 관할권 서비스 불가
   - 사용자가 허용된 지역에 있음을 증명
   - 도시/주소를 공개하지 않고 접근 허용
   - 사용자 프라이버시로 규정 준수 운영

2. **라이선스 서비스 접근**
   - 특정 관할권에서 라이선스된 파생상품 거래
   - 사용자가 적격 관할권 멤버십 증명
   - 합법적으로 라이선스된 플랫폼에서 거래
   - 규제 요구사항 충족

3. **지역 토큰 출시**
   - 토큰 출시가 미국 거주자 제외 (Reg S)
   - 비미국 사용자가 관할권 증명
   - 규정 준수 오퍼링에 참여
   - 발행자가 규제 위험으로부터 보호

4. **여행 거래자**
   - 미국에 일반적으로 거주, EU로 여행
   - 해외에서 위치 재증명
   - 일시적으로 EU 전용 기능 접근
   - 집에서 정상 접근으로 복귀

## 실제 제품 및 사용자 경험

### 1. "최소 위치 공개" - 도시/주소 대신 국가만 증명

**제품 설명**:
규제 준수에 필요한 최소한의 위치 정보(국가/지역)만 증명하고, 도시나 정확한 위치는 절대 공개하지 않는 프라이버시 지오펜싱.

**일반 사용자 경험**:
- 이글로벌씨(30세)는 서울에서 DeFi 서비스 이용
- 일반 지오펜싱: "서울시, 한국" 또는 IP 기반 위치 노출
- 최소 공개: "한국 내 위치" ZK 증명만 제출
- "서울인지 부산인지"는 서비스도 알 수 없음
- 규제(한국 허용)는 충족, 세부 위치는 비공개

**관찰 가능한 이점**:
- 규제 요구사항의 최소 충족
- 거주 도시/지역 프라이버시 보호
- 위치 기반 프로파일링 방지

### 2. "위치 이력 제로" - 과거 위치 기록 없음

**제품 설명**:
매 접속 시 위치를 새로 증명하되, 과거 위치 이력이 어디에도 저장되지 않는 서비스. 사용자의 이동 패턴 분석이 불가능합니다.

**일반 사용자 경험**:
- 박여행(28세)은 한국→일본→미국 출장 중 서비스 이용
- 일반 시스템: "박씨가 이번 주 3개국 방문" 이력 축적
- 위치 이력 제로: 각 증명이 일회성, 이전 기록 없음
- 서비스는 "지금 허용 지역인가"만 알고 이동 패턴 모름
- 출장 일정과 방문 국가가 비공개로 유지

**관찰 가능한 이점**:
- 이동 패턴 분석 완전 차단
- 여행/출장 이력 프라이버시 보호
- 위치 데이터 축적 원천 방지

### 3. "프라이버시 우선 컴플라이언스" - 프로토콜에도 위치 숨김

**제품 설명**:
프로토콜 운영자조차 사용자의 구체적 위치를 알 수 없고, "제재국 아님" 증명만 받는 완전 프라이버시 규제 준수.

**일반 사용자 경험 (프로토콜 운영자 관점)**:
- XYZ 프로토콜은 OFAC 제재국 차단 필요
- 일반 방식: 사용자 국가를 DB에 저장 → 데이터 유출 위험
- 프라이버시 방식: "제재국 목록에 없음" ZK 증명만 수신
- 프로토콜은 사용자가 "어느 나라인지" 모름
- 데이터 유출 사고 시에도 위치 정보 없음

**관찰 가능한 이점**:
- 위치 데이터 수집 자체를 안 함
- 데이터 유출 위험 제로
- GDPR 등 데이터 규제 자동 준수
