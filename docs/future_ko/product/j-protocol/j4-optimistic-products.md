## 제품 시나리오

### 1. "프라이버시 폴백" - 분쟁 시에도 프라이버시 유지

**제품명**: 제로 노출 분쟁 해결 시스템

**제품 설명**:
낙관적 모드에서 분쟁 발생 시 ZK 증명으로 해결하되, 분쟁 과정에서도 거래 세부내용이 공개되지 않는 프라이버시 보존 분쟁 해결. 챌린지 과정에서 거래 내용을 드러내지 않습니다.

**일반 사용자 경험**:
김하이브리드씨(29세, 개인 투자자)의 거래에 챌린지가 발생했습니다.

- **문제 상황**: 일반 낙관적 롤업의 사기 증명(fraud proof)은 "이 거래가 잘못됐다"를 증명하기 위해 거래 세부내용을 공개합니다. "김씨가 $500를 A에게 전송" 같은 정보가 분쟁 과정에서 드러나, 프라이빗 거래임에도 내용이 노출됩니다.

- **프라이버시 폴백 사용**: 분쟁 발생 시 ZK 증명을 생성하여 "이 거래가 유효하다/무효하다"만 증명합니다. 증명은 거래가 올바른 규칙에 따라 실행되었는지를 검증하지만, 거래 금액, 상대방, 거래 유형 같은 세부내용은 전혀 공개하지 않습니다.

- **결과**: 김씨의 거래 내용은 분쟁 상황에서도 보호됩니다. 챌린저는 "무언가 잘못되었다"는 의심만 제기할 수 있고, 검증 과정에서도 "유효/무효" 결과만 얻을 뿐 거래의 구체적 내용은 알 수 없습니다.

**관찰 가능한 이점**:
- **분쟁 시에도 거래 프라이버시 유지**: 챌린지로 인한 정보 노출 방지
- **챌린지로 인한 정보 노출 방지**: 공격자가 프라이버시 침해 목적으로 챌린지 악용 불가
- **프라이버시와 분쟁 해결의 양립**: 보안과 프라이버시 동시 확보

### 2. "숨겨진 가치 계층" - 어떤 거래가 ZK인지 숨김

**제품명**: 균일 보안 레벨 인터페이스

**제품 설명**:
고가치 거래에 ZK 증명을 사용하되, 어떤 거래가 ZK로 처리되었는지 외부에서 구분할 수 없게 하는 서비스. 보안 수준으로 거래 가치를 추론할 수 없게 합니다.

**일반 사용자 경험**:
게이머 박플레이씨(24세)가 레어 아이템 거래($1,000+ 가치)를 진행합니다.

- **문제 상황**: 일반 하이브리드 시스템에서는 고가치 거래는 ZK 모드로, 저가치 거래는 낙관적 모드로 처리합니다. 이 구분이 관찰 가능하므로, 공격자들이 "ZK 모드로 처리된 거래 = 고가치"로 추론하여 해당 사용자를 타겟팅합니다.

- **숨겨진 계층 사용**: 모든 거래가 외부에서 동일한 형태로 제출됩니다. 내부적으로는 가치에 따라 ZK/낙관적 모드를 선택하지만, 온체인 트랜잭션 형태는 모두 동일하므로 어떤 모드인지 구분할 수 없습니다. 증명 크기와 형태도 표준화되어 차이가 없습니다.

- **결과**: 박씨의 레어 아이템 거래가 보호됩니다. 공격자들은 "이 거래가 고가치인지"를 판단할 수 없으므로, 레어 아이템 소유자를 식별하거나 타겟 공격을 할 수 없습니다.

**관찰 가능한 이점**:
- **고가치 거래자 타겟팅 방지**: 보안 수준으로 가치 추론 불가
- **ZK/낙관적 구분으로 인한 정보 누출 차단**: 모든 거래가 동일하게 보임
- **거래 가치 추론 방지**: 가치 기반 공격 차단

### 3. "프라이버시 우선 마이그레이션" - 전환 과정도 비공개

**제품명**: 투명 모드 전환 시스템

**제품 설명**:
낙관적에서 ZK로 마이그레이션할 때 어떤 사용자가 어느 단계에 있는지 추적이 불가능한 프라이버시 마이그레이션. 보안 업그레이드 상태로 사용자를 분류할 수 없게 합니다.

**일반 사용자 경험**:
ABC 프로토콜 운영진이 점진적 ZK 전환을 진행 중입니다.

- **문제 상황**: 일반 마이그레이션에서는 "사용자 X는 이미 ZK 전환 완료, 사용자 Y는 아직 낙관적 모드" 같은 상태 정보가 관찰 가능합니다. 공격자들이 "ZK 전환 안 한 사용자"를 타겟팅하여 낙관적 모드의 상대적으로 약한 보안을 공격합니다.

- **프라이버시 마이그레이션 사용**: 모든 사용자의 거래가 동일한 인터페이스를 통해 제출됩니다. 백엔드에서 ZK/낙관적 처리가 결정되지만, 프론트엔드는 완전히 동일하므로 사용자가 어느 모드를 사용하는지 외부에서 알 수 없습니다.

- **결과**: 마이그레이션 진행 상황이 숨겨집니다. 공격자들은 "이 사용자는 아직 낙관적 모드"를 식별할 수 없으므로, 보안 수준 차이를 악용한 선택적 공격이 불가능합니다.

**관찰 가능한 이점**:
- **마이그레이션 상태로 사용자 분류 방지**: 보안 레벨로 구분 불가
- **보안 수준 차이를 악용한 공격 차단**: 약한 보안 사용자 타겟팅 불가
- **균일한 보안 인식 유지**: 모든 사용자가 동등하게 보호됨
