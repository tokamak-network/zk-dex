## 제품 시나리오

### 1. "프라이버시 유지 압축" - 압축해도 정보 노출 없음

**제품명**: 제로 누출 증명 압축 서비스

**제품 설명**:
증명을 압축할 때 프라이빗 정보가 압축 과정에서 노출되지 않도록 보장하는 프라이버시 보존 압축 서비스. 작은 증명 크기와 완전한 프라이버시를 동시에 달성합니다.

**일반 사용자 경험**:
이모바일씨(25세, 모바일 우선 사용자)는 프라이빗 거래를 모바일에서 사용합니다.

- **문제 상황**: 대형 STARK 증명(100KB+)을 모바일에서 전송하면 데이터 비용이 많이 들고 느립니다. 일반 압축 방식은 효율적이지만, 압축 과정에서 거래 크기나 복잡도 같은 메타데이터가 암묵적으로 노출될 수 있습니다. 예를 들어 "압축률이 낮다 = 복잡한 거래"로 추론 가능합니다.

- **프라이버시 압축 사용**: STARK 증명을 SNARK로 래핑하되, 래핑 과정에서 원본 증명의 구조적 정보를 완전히 제거합니다. 최종 256바이트 증명은 모든 거래 유형에 대해 동일한 크기와 형태를 가지므로, 압축된 증명에서 원본 거래 정보를 전혀 추출할 수 없습니다.

- **결과**: 이씨는 모바일에서 빠른 전송(256B만 전송)과 완전한 프라이버시를 동시에 얻습니다. "이 거래가 단순한지 복잡한지", "어떤 유형의 거래인지" 같은 정보가 압축으로 인해 노출되지 않습니다.

**관찰 가능한 이점**:
- **효율성과 프라이버시 동시 확보**: 작은 증명이지만 정보 누출 제로
- **압축 과정에서 메타데이터 보호**: 거래 복잡도나 유형 추론 불가
- **모바일 환경에서도 완전한 프라이버시**: 대역폭 제약 속에서도 프라이버시 유지

### 2. "익명 크로스롤업" - 롤업 이동 시 연결고리 제거

**제품명**: 프라이버시 보존 브릿지 압축

**제품 설명**:
롤업 간 브릿지 증명을 압축할 때 "어느 롤업에서 어느 롤업으로" 연결 정보를 제거하는 프라이버시 브릿지. 크로스체인 이동의 출발지와 목적지 연결을 완전히 숨깁니다.

**일반 사용자 경험**:
박브릿저씨(30세, 멀티체인 투자자)는 A 롤업에서 B 롤업으로 자산을 이동합니다.

- **문제 상황**: 일반 브릿지 증명에는 "출처 롤업 A의 상태 루트"와 "목적지 롤업 B의 상태 루트" 정보가 포함되어, 압축 후에도 "A→B 이동"이라는 연결 정보가 남습니다. 이를 분석하면 사용자의 크로스체인 이동 패턴을 추적할 수 있습니다.

- **익명 브릿지 사용**: 브릿지 증명을 압축할 때 출발지와 목적지 정보를 통합된 형태로 변환합니다. 최종 압축 증명은 "유효한 크로스체인 상태 전환"만 증명하며, 어느 체인에서 어느 체인으로 이동했는지 정보는 포함하지 않습니다.

- **결과**: 박씨의 크로스롤업 이동 기록이 보호됩니다. 분석 도구로 "이 사용자는 A, B, C 롤업 모두 사용한다"는 프로필을 만들 수 없으며, 롤업 간 자금 흐름 추적도 불가능합니다.

**관찰 가능한 이점**:
- **롤업 간 자산 흐름 추적 방지**: 출발지-목적지 연결 정보 제거
- **멀티롤업 사용 패턴 숨김**: 어떤 롤업 조합을 사용하는지 비공개
- **프라이버시 보존 크로스롤업 이동**: 체인 간 이동이 익명화됨

### 3. "제로 메타데이터 압축" - 증명 시스템 정보도 숨김

**제품명**: 출처 비공개 증명 변환 서비스

**제품 설명**:
STARK-to-SNARK 변환 시 어떤 증명 시스템을 사용했는지, 어떤 프로토콜에서 왔는지 정보가 모두 제거되는 서비스. 압축된 증명의 출처를 완전히 익명화합니다.

**일반 사용자 경험**:
최프로토콜씨(38세, 프로토콜 개발자)는 자신의 DeFi 프로토콜에 특화된 STARK 시스템을 운영합니다.

- **문제 상황**: 각 프로토콜이 사용하는 STARK 시스템은 고유한 파라미터를 가지므로, 증명을 SNARK로 변환한 후에도 "이 증명은 XYZ 프로토콜에서 왔다"는 정보가 증명 구조에서 추론 가능합니다. 이를 통해 사용자의 프로토콜 사용 내역이 노출됩니다.

- **제로 메타데이터 압축 사용**: 증명 변환 시 프로토콜 특화 파라미터를 표준화된 형태로 변환합니다. 모든 프로토콜에서 온 증명이 동일한 SNARK 형태로 변환되므로, 최종 증명에서 출처 프로토콜을 식별할 수 없습니다.

- **결과**: 사용자들이 최씨의 프로토콜을 사용해도, 압축된 증명만으로는 "이 사용자가 XYZ 프로토콜을 썼다"는 것을 알 수 없습니다. 프로토콜별 사용자 활동 분리가 가능해집니다.

**관찰 가능한 이점**:
- **프로토콜 사용 내역 비공개**: 어떤 프로토콜을 사용했는지 숨김
- **증명 출처 추적 방지**: 증명 시스템으로 프로토콜 식별 불가
- **프로토콜 간 활동 연결 차단**: 멀티 프로토콜 사용 패턴 숨김
